## Notes

1. **Tier.** No tier is set for any of these 11 widgets. §7.1 defines the tiers in general but names none for R0, and no code sets one. Left unset, not guessed.
2. **Promotion: a conflict to settle.** §9 R0 lists "promote or keep as sandbox" in the scorer's flow. `PILOT_MATCH_PHASE2.md` line 24 says promotion is "Built in R1, when a school exists to take the match". This registry takes the design doc's side: keep-as-sandbox is R0 (it is the default, line 36), promotion and the awaiting list are R1. Kameel to confirm.
3. **Pilot access is a database grant, not a capability.** The `pilot.scorer` grant (db/151:124, checked by `pilot_status()` at db/151:637) is not in `capabilities.mjs`. The registry names it rather than inventing a capability. Promotion has no capability in `capabilities.mjs` yet.
4. **Fixture resume not traced.** `scorer.resume_session` is verified for practice and pilot matches only (setup.jsx:523-536, pilotList.jsx:116). The fixture's own resume path in `scorer/engine.jsx` was not followed.
5. **Corrections on a pilot.** `pilot-api.mjs` says the pilot does not take "an official's amendment" (header, the `scoring.amend.request` path is the fixture's). So a correction after finish has no pilot path. Live undo and revise do exist.
6. **Status change priority.** §3E's table puts "Match status changed" in the P0 column but calls it "informational, not an alarm". The registry uses P0 as the table says. Kameel may prefer P1 or P2.
7. **Spectator copy.** The pilot public scorecard follows the repo's §3E correction: score and team names only. Typed player names are never sent to the public read (pilotWire and §3E).
8. **Public routes are off by default.** `services/api/server.mjs:54` says the signed-out pages run only with `PUBLIC_PAGES=on`. Any public rows here are unreachable today unless that switch is on.

## Fields I could not fill

- **`tier`**: not set on any row (note 1).
- **`analytics_event`**: every name is proposed. No analytics layer was found in the scorer or the public match page. `PublicMatch.jsx` mentions "analytics" only as a tab name.
- **`freshness`** for the pilot list and the pilot scorecard: the pilot API header lists no read timestamp, so the cell says so.
- **`scope`** for the pilot spectator: the slug is not defined until slice 4.
- **`confirmed`** for a pilot: a pilot has no result confirmation, so the state has no pilot meaning. Cancelled maps to `abandoned`.
- **Empty and error copy** marked "proposed" where the code has none.
